# 导歌与自动编排

## 怎么玩自己的歌

1. 在首页点击 **CHOOSE / IMPORT SONG**。
2. 选择 **Easy**（更多恢复时间，仅直拳）或 **Normal**（直拳和勾拳）。
3. 点击 **IMPORT SONG…**，选择本地 MP3、WAV 或 Ogg Vorbis 文件。
4. 等待本地分析完成；进度条显示分析进度，可以取消。
5. 回到首页后可看到歌名、时长、BPM 和音符数量，按 Space 开始整首歌。
6. 下次打开曲库，选中歌曲，再点 **PREPARE SELECTED SONG** 即可重玩。相同设置复用已保存的谱面。

支持长度 8 秒–10 分钟、文件不超过 64 MiB。FLAC、AAC、Ogg Opus、流媒体链接和 DRM 文件暂不支持，可自行转换为 PCM WAV、MP3 或 Vorbis。纯静音或不足以编排 4 个动作的音频会提示无法生成，不影响当前选曲。

选择 **USE DEMO LOOP** 可以切回内置演示曲。当前界面是英文原型；本版在 Linux 开发工程中实现，Android 系统选歌与存储权限尚未适配和实测。

## 自动编排如何工作

完全使用 Godot 本地解码器和 GDScript，不需要服务端、API key、FFmpeg 或额外模型。FFmpeg 仅用于开发者重新生成测试素材。

- 后台线程解码音频，以约 20ms 窗口分析双声道能量，提取正向能量变化作为起音线索。
- 用前两分钟的起音自相关估计约 60–176 BPM 的主节奏，并估计节拍网格起点。
- 根据四秒能量区域调整密度：较安静部分更稀疏、显著静音处跳过动作，较强段落允许勾拳。
- 始终交替左右手，Normal 最小间隔约 0.7 秒，Easy 约 1.1 秒；勾拳后至少约 1 秒恢复，每八个动作额外留恢复时间。
- 开头至少三秒用于准备，结尾留半秒；音符、长度、进度条和结算均跟随导入歌曲。

这是第一版信号处理启发式。**能量分段不等于理解音乐情绪或识别主歌/副歌**，出拳间隔限制也不代表经过运动科学验证的训练课程。自由速度、弱鼓点、切分或复杂编曲可能估错拍、出现倍速或半速问题；暂不支持变速节拍跟踪和谱面编辑。

如果首页显示 **ESTIMATE / CHECK BEAT**，说明节奏相关性较弱。可以在曲库勾选 **Correct BPM manually**，输入 60–180 BPM，再准备同一首歌。手动 BPM 会重新生成独立谱面，并保留旧谱面；它只修正速度，尚不提供节拍偏移调节。

## 重玩、去重和记录

歌曲身份使用**原始文件字节的 SHA-256**，重命名文件不会重复入库；重新编码的文件属于新音源。谱面身份由歌曲 ID、算法版本 `energy-grid-v1`、强度与 BPM 覆盖值共同确定。生成后保存为 JSON，首次使用和再次读取统一序列化精度，重玩不重新随机生成。

保存位置：

```text
user://songs/<音源 SHA-256>/
  audio.mp3（或 audio.wav / audio.ogg）
  song.json
  <谱面 ID>.json
```

原音频以本地副本保存，移动或删除原文件不会让已导入的歌曲失效。无需也不会上传音频或谱面。写入使用临时文件后重命名；保存失败、读取失败和格式问题会显示在曲库。无效谱面缓存会自动重建。当前没有应用内删歌按钮，可退出应用后删除对应歌曲目录；不会删除原文件。

模拟练习记录继续写入 `user://simulation_history.json`，增加 `song_id`、`chart_id` 和真实曲目时长。记录不是正式运动成绩，不生成官方 Full Combo。

## 验证覆盖与边界

自动化检查使用原创合成波形和压缩成 MP3 / Vorbis 的同源测试素材，覆盖不同 BPM、能量段落、静音、拳法交替与间隔、确定性、手动 BPM、三种格式解码、本地副本、重命名去重、缓存重用与修复、无效输入、取消分析、后台选歌及全曲结束。

测试素材不等于真实音乐库；尚未评估真实歌曲上的估拍准确率，也未实测系统原生文件选择窗口、真实音频延迟或 Android 设备。建议先用节拍清晰、速度稳定的歌曲体验这一版。
