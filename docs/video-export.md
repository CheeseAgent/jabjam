# 离线 MP4 导出

## 如何写课程

从 [自动编排示例](../courses/neon-round.json) 或 [手排八动作示例](../courses/eight-moves.json) 复制一份 JSON。时间以音乐起点为零，单位为秒。一份配置对应一首歌、一条连续时间轴和一个视频文件。

也可以把自动课程转成手排课程，保留实际编排后的时间、动作、画面设置和生效的命令行覆盖值。用法见 [从自动谱开始改](../README.md#从自动谱开始改)。`--write-course` 用 ffprobe 读取原曲，自动编排或生成内置曲时会调用 Godot。之后可直接编辑输出的 JSON，再用相同的导出命令生成 MP4。

| 字段 | 作用 |
| --- | --- |
| `version` | 当前填整数 1。 |
| `course.song_title` | 歌名，最多 128 个字符。调用时的 `--song-title` 优先，其次是这个字段、音频内嵌标题、文件名。内置曲名为 JabJam Demo Loop。标题也写入 MP4 元数据。旧配置里的课程名 `title` 可保留。 |
| `course.music` | `builtin:demo` 生成原创演示音乐，也可填相对 **JSON 所在目录** 的本地 MP3、WAV 或 Ogg Vorbis 路径。导入范围为 8 秒至 10 分钟，最多 64 MiB。 |
| `course.difficulty`、`course.bpm` | 自动编排可选，强度为 `easy`、`normal`、`hard` 或 `expert`，默认 normal。省略 BPM 会估拍，也可用 60–180 的数值覆盖估计。手工动作按给定时间播放。 |
| `course.movement_set` | `classic` 为基础出拳、`mixed` 为原有混合动作、`padwork` 为教练喂靶式组合拳（Normal、Hard、Expert 自动课程）。三种模式相互独立。 |
| `course.lyric_starts` | 可选，按升序填写原曲里每句开唱的秒数，如 `[4.28, 8.15, 10.32]`。自动喂靶组合谱优先用这些时间，其次读取音频旁的同名 `.lrc`。 |
| `course.beat_offset_ms` | 自动谱拍点时间校准（毫秒，-250～250；负数提前）。命令行或 Actions 可用 `--beat-offset-ms` 覆盖。不会更改 BPM。 | 
| `course.min_gap` | 可选，两次出拳之间至少留多少秒。命令行可用 `--min-gap` 覆盖，难度自带的下限始终生效。 |
| `actions` | 默认 `"auto"`。手工编排填按时间递增的数组，例如 `[{"time":4.0,"action":"left_hook"},{"time":5.5,"action":"right_hook"}]`。直拳为 `left_jab`、`right_jab`，摆拳为 `left_hook`、`right_hook`，上勾拳为 `left_uppercut`、`right_uppercut`，侧步为 `step_left`、`step_right`。 |
| `picture.size`、`picture.fps` | 默认 `[1280,720]` 和 24 fps。也支持 960×540、640×360，以及 25 / 30 fps。 |
| `picture.approach_seconds` | 提前多少秒让方块出现，可设 0.7–4 秒，默认 2。开头不足预告时长的动作会在第一帧已经进入轨道。 |
| `picture.left_color`、`picture.right_color` | 两侧轨道、方块及碎片使用的颜色，格式为 `#RRGGBB`。选择相互区分且与深色场景有对比的颜色。 |
| `picture.scene` | 在渲染前选定整首歌的背景。可选 `neon`（默认）、`classic`、`undersea-office`、`jellyfish-radio`、`panda-hotpot` 或 `moon-carrots`。命令行 `--scene` 或 Actions 场景下拉框可覆盖课程设置。旧课程的 `art-tour` 会使用它原来的开场背景海底摸鱼办公室。 |

GitHub 托管任务只能访问该次检出和构建时包含的素材。示例使用仓库原创音频。自有歌曲可在持有该文件的机器或私有仓库使用；公共仓库示例选用可公开分发的音频。Docker 构建上下文受根目录 `.dockerignore` 约束。

## 拍点与自动谱诊断

自动谱使用歌曲的局部能量包络决定每八拍的出拳密度：安静段落约 2 次/8 拍，普通段落约 4 次/8 拍，强段落尝试 6 次/8 拍（摆拳恢复规则仍会删掉拥挤音符）。用较长拍组细化 BPM，从全曲起音估计起拍相位，再在每拍前后四拍内寻找一致的局部偏移。演示曲有明显的弱—中—强—桥—尾声五段，适合对比。

导出同时输出 `*.chart.json` 审核文件，`source_beats` 保存校准前的全曲拍点，`notes` 保存应用 `beat_offset_ms` 后实际使用的动作秒数。文件还记录四秒区段能量和节奏置信度。存在持续时差时调整 `beat_offset_ms`；BPM 估错时需先人工修正 BPM，否则单纯偏移无效。

## 教练喂靶组合拳（padwork）

设置 `course.movement_set = "padwork"` 且难度为 Normal、Hard 或 Expert，自动从**可扩展的组合拳库**中选择成套拳组，而不是逐拳随机换类型：

- 热身组合：直直、直摆。
- 常规组合：直直摆、直直勾、直摆直、直勾直、直直摆直、直直勾直。
- 高能量组合：直直摆勾直、直直摆直勾、直勾直摆直、直直勾摆直、直摆直勾直、直直摆直摆。

每个难度组里的同一套路先左起手、再右起手镜像练习，然后轮换下一套。每次使用完整的组合，按拳法恢复时间拉开相邻动作。音乐能量决定优先选择哪个难度组，有歌词时间时还要给下一组留出收拳时间。组合库定义于 `video/choreography.py` 的 `PADWORK_COMBOS`。

组间空拍提示回架，首拳前两拍提示下一组及起手侧，出手后顶部显示当前组合和拳序，导出的 `*.chart.json` 中每次动作额外带有 `combo_name`、`combo_id`、`combo_step`、`combo_total`、`combo_no` 以便检验重复练习。此模式仅用于自动视频谱，手排时间轴保持不变，`easy` 不会强制做复杂组合。

`--write-course` 会把相同的组合提示保存在手排课程中。手改时可同时修改组合名、当前拳序和总拳数，也可以删除该动作的组合字段，只保留 `time` 和 `action`。时间已经包含自动谱采用的拍点偏移，重新导出手排课程时直接使用这些秒数。

只有音频时，组合按节拍网格起手。恢复时间不足时顺延到下一个可用拍点。弱鼓点、显著变速和小节强拍的识别仍需试听校验。

### 按歌词起拳

只有音频时，小奶茶可以先按交接手册去国内音乐平台找同版录音的句首时间。[去哪里找逐行歌词](maintenance-playbook.md#给新歌找逐行歌词)

把同一录音版本的 UTF-8 逐行歌词与音频放在一起，例如 `round.mp3` 和 `round.lrc`。下面三行标记三次开唱，包括提前进拍的句首。

```text
[00:04.28]抬起手
[00:08.15]往前一步
[00:10.32]跟着我再来
```

方块在句首到达击打线，小奶茶同时出第一拳。后几拳使用实测拍点。默认 `course.lyric_phrasing = "paired"`。如果连续两行各不超过约四拍半，可以从第一句起一套跨行组合，给第三句留下完整恢复时间。设置 `"single"` 即使用逐行边界。放不下时逐级尝试较短的完整组合。开头三秒用于准备，间奏期间等下一条句首标记。

同一时间的译文只算一句，多时间标签的重复歌词分别计入。空行和单独的 `[Chorus]` 等段落标签不触发动作。LRC 的 `[offset:+100]` 表示歌词提前 100 毫秒。`beat_offset_ms` 用于校准鼓点，首拳始终以歌词时间为准。只有音频时沿用原来的八拍分组。

`--check` 会显示读到的歌词行数。自动导出的 `.chart.json` 记录组数、可见歌词行数与句首秒数 `lyric_starts`，通过 `combo_step == 1` 可找到对应的首拳。`--write-course` 保存最终动作时间，之后编辑或播放这份手排谱不再需要 LRC。

### 副歌招牌组合

在 Normal、Hard 或 Expert 的自动喂靶课程里，给同一句副歌每次起唱的位置各标一次。时间从这版录音开头算起，单位为秒，按升序填写。若已有同版 LRC，直接抄那一句的时间。手边只有音频也可以手标，其他段落继续按鼓点编排。[完整示范课程](../courses/chorus-signature.json)

```json
{
  "version": 1,
  "course": {
    "music": "builtin:demo",
    "movement_set": "padwork",
    "chorus_starts": [8, 18, 28]
  }
}
```

第 8 秒左起学三拳，第 18 秒右起镜像，第 28 秒左起加长。只标一次或两次就练基础组合。标四次或更多时，中间各遍左右交替，只有最后一遍尝试加长。末句如果没有足够拍点或回架时间，就保留三拳。想给另一首歌指定不同动作，可以选填 `course.chorus_combo`。

| `chorus_combo` | 基础三拳 | 末遍五拳 |
| --- | --- | --- |
| `jab_jab_hook`（默认） | 直直摆 | 直直摆勾直 |
| `jab_jab_uppercut` | 直直勾 | 直直勾摆直 |
| `jab_hook_jab` | 直摆直 | 直摆直勾直 |
| `jab_uppercut_jab` | 直勾直 | 直勾直摆直 |

首拳落在标记时刻，后续动作落在经过偏移校准的鼓点上。招牌组合优先保留，前后过近的普通组整组让位。两处标记之间放不下完整三拳与恢复拍，或标记落在前三秒或曲尾时，导出器会指出需要调整的秒数。Easy、classic 和 mixed 继续使用各自的编排。

`--check` 可查看有效标记数。`--write-course` 会冻结已排好的动作和 `chorus_cue`，再次导出手排谱时沿用这些动作。自动谱的 `.chart.json` 保存 `chorus_starts`，筛选含 `chorus_cue` 且 `combo_step == 1` 的动作即可核对每一遍的起手、拳数和实际时刻。

## 难度和出拳间隔

| 难度 | 一般出拳 | 摆／勾拳之后或同手连打 | 侧步前后 | 高能量喂靶组合 |
| --- | ---: | ---: | ---: | --- |
| Easy | 1.10 秒 | 1.35 秒 | 1.75 秒 | 稀疏直拳 |
| Normal | 0.45 秒 | 0.90 秒 | 1.50 秒 | 五拳 |
| Hard | 0.38 秒 | 0.70 秒 | 1.40 秒 | 六拳 |
| Expert | 0.32 秒 | 0.50 秒 | 1.25 秒 | 八拳 |

动作仍要落在可用拍点，短句可以选择短组合。命令行 `--difficulty` 覆盖课程难度，作者显式指定的较长 `min_gap` 依然生效。

自动编排会跳过太密的候选拍点，并保持左右交替。手排模式保留作者指定的拳法与时刻，间隔太短时会报告相邻两个时刻和要求的间隔，再由作者调整。画面中的碎裂、光环和火花始终对应保留下来的拳点。

## 时间轴与导出

自动模式在独立 Godot 无界面进程中调用原有 `SongLibrary.import_song`，得到动作及时间戳。手工模式直接使用 JSON 时间戳。以每帧的音频时间计算方块位置：远端出现、沿透视轨道放大、到线、裂成碎片。视频使用最接近动作时间的帧显示教练到位、碎裂和当前拳序。帧间取整误差通常不超过半帧，24 fps 约为 21 ms，30 fps 约为 17 ms。手排动作的原始秒数保存在课程里。左摆拳在左轨向右弯，右摆拳在右轨向左弯。上勾拳使用向上挑的 J 形箭头；侧步用地面脚印和向外箭头，到拍点脚印落地并出现波纹。

Python 用 Pillow 逐帧绘制，FFmpeg 从管道读取 RGB 并混入原曲音轨。内存中只保留当前画面与有限的字形图像。导出写入同一输出目录下的临时文件，编码成功后才替换目标 MP4。临时曲库和中间文件随任务结束清理。

## 歌词与连击预设

`picture.lyrics` 或 `--lyrics` 可以选 `off`（默认）、`fade`（淡入淡出）、`rise`（上浮）、`pulse`（随鼓点伸缩的亮条）。渲染前选定，歌词会烧录到 MP4。文字来自同名 UTF-8 LRC，或内嵌 `course.lyric_lines`，后者优先。手排和 Easy 也可以单独显示歌词。单独的 `lyric_starts` 和“句 01”只能用来定时，开启效果时 `--check` 会报告可显示的行数。空行用于清屏，长间奏中一行最多停留七秒。冻结开启了歌词的课程会保留显示文本和视觉拍点。

`picture.combo_style` / `--combo-style` 提供 `minimal`、`arcade`（默认）和 `ring`。环每十个动作走完一圈。用 `picture.combo_side` / `--combo-side` 选择 `auto`、`left`、`right` 或 `off`。落到第二个动作时开始显示计数；休息达到四拍且至少两秒时重新计数。视频依据谱面累计，正放与拖动到同一帧会得到相同结果。

## 资源与验收

早期 24 秒素材的独立实验中，编排进程的峰值 RSS 约 60 MiB，单线程低延迟编码约 70 MiB，另一组编码参数约 448 MiB。现在每次工作流都用下面的容器限额跑实际成片，运行摘要提供当次测量。[早期实验记录](https://github.com/CheeseAgent/jabjam/pull/8)

工作流使用独立的 `video-export` 镜像目标。镜像构建在 GitHub runner 上进行。每次导出使用新的离线容器，限制为 **2 CPU、300,000,000 字节内存、无额外 swap**，构建阶段不套用此限额。实际数字写在产物的 `*.resources.json` 中：导出耗时、成片时长和大小、导出完成时读取的 cgroup v2 内存峰值。该值包含容器内进程及计入其账下的缓存。三分钟测试的峰值还包括容器内的测试音频准备。

- 默认自动课程验证音乐分析、动作编排与 720p 导出。额外使用三分钟测试曲验证较长时间轴。
- 手排课程逐帧抽查四种拳法，对比靠近、拍点转换和碎片外扩。两种勾拳均检查成片中箭头尖端的朝向。
- 媒体验证检查 H.264 / AAC、分辨率、帧数、起止时间及音轨信号。手排样片还对比两个时点的原曲和导出音频波形。

这些样例覆盖指定时长、帧率与素材。编解码器、声道数及源文件大小也会影响峰值，配置允许导入的最长文件仍需按实际素材测试。

## 扩展动作

在 [动作表](../video/movements.py) 注册 ID，用手排课程放一个拍点，再到 [cue_art.py](../video/cue_art.py) 添加箭头或脚印。需要自动生成时，可在 [choreography.py](../video/choreography.py) 增加编排规则或组合模板。按任务查找入口、运行回归测试和抽帧验收的命令见 [AGENTS.md](../AGENTS.md)。
